# Mabinogi Mobile Rune Optimizer

마비노기 모바일 **시즌2 룬 추천기** (비공식).

### → **https://rune.askhyung.com** — 설치 없이 바로 쓰세요

여기는 그 서비스의 **소스 코드**입니다. 운영 중인 사이트와 인프라는 따로 관리하고,
이 저장소는 **`data/` 에 대한 기여를 받기 위해** 공개합니다.

> **기여를 받고 싶은 곳: [`data/`](data/)**
> 직업 21개의 전투 수치와 룬 조건부 옵션이 JSON 으로 들어 있습니다. **JS 를 몰라도
> 숫자와 문장만 고치면 됩니다.** 지금 검증이 필요한 항목은 [HELP-WANTED.md](HELP-WANTED.md)
> 에 자동으로 모여 있습니다.

## 무엇을 하는 도구인가

전투력 숫자를 보는 도구가 아닙니다. **한 대 때렸을 때 실제로 들어가는 대미지**를 기준으로
룬을 비교합니다.

1. **측정** — 룬 하나를 뺐다 꼈다 하며 스탯창 공격력 변화를 입력하면, 깡공(A)과 공증(B)을
   역산합니다. 스탯창만 봐서는 이 둘이 분리되지 않아서, 이 단계가 필수입니다.
2. **추천** — 부위별 교체 후보와 최적 세트를 계산합니다. 전수 탐색은 조합이 3억을 넘어
   불가능하므로 언덕오르기 + 시너지 프로브를 씁니다.
3. **시나리오** — 조건부 옵션이 하나도 안 터지는 `최소`, 가동률을 반영한 `기대값`,
   전부 터지는 `최대` 세 기준으로 각각 계산합니다.

계산에 안 들어간 효과(쿨감, 이동기, 스킬 변형 등)는 **미계산 항목**으로 따로 보여줍니다.
0으로 계산했다는 사실을 감추지 않는 것이 이 도구의 원칙입니다.

## 수치가 틀렸으면 — 개발 없이

**[rune.askhyung.com/report](https://rune.askhyung.com/report) 에 세 칸만 적으면 됩니다.**
GitHub 계정이 없어도 됩니다.

가장 급한 것은 **게임 툴팁에 없는 숫자**입니다 — 밤의 축복이 실제 로테이션에서 몇 초마다
도는지, 그 패시브가 사냥 중 몇 % 켜져 있는지, 평소 딜에서 연타·강타 비율이 어떻게 되는지.
이 값들은 지금 추측으로 채워져 있고, 여기가 틀리면 추천 순위가 통째로 틀립니다.

받은 제보는 같은 페이지에 **어떻게 처리했는지까지 공개**됩니다. 반영하지 않은 것도
왜 지금 값이 맞는지 적어 남깁니다.

## 직접 고치실 분 — 개발 환경

`npm install` 이 없습니다. **의존성이 0개**라 clone 하면 바로 시작합니다.

```bash
git clone https://github.com/mobinogi-tools/rune-optimizer.git
cd rune-optimizer
npm run dev              # http://127.0.0.1:8123/runes.html — 빌드 없이 원본을 그대로 띄웁니다
```

파일을 브라우저로 직접 여는 것(`file://`)은 안 됩니다 — 페이지가 ES 모듈을 쓰는데
브라우저가 `file://` 에서 모듈을 막습니다. `npm run dev` 는 의존성 없이 Node 만 씁니다.

`data/` 를 고친 뒤 이 세 개로 스스로 검증할 수 있습니다 (Node.js 20 이상):

```bash
node tools/build-data.mjs      # data/ → src/gen/ 재생성. 생성물까지 커밋합니다
node tools/validate-data.mjs   # 스키마·참조·근거 검사
npm test                       # 테스트 164개
```

그리고 `runes.html` 을 새로고침해 화면에서 확인하면 끝입니다. 자세한 규칙은
[CONTRIBUTING.md](CONTRIBUTING.md), 코딩 에이전트를 쓰신다면 [AGENTS.md](AGENTS.md) 를 봐주세요.

수치를 바꾸는 기여에는 **`evidence`(어떻게 확인했는지)가 따라붙습니다.** 무겁지 않습니다 —
게임에 적혀 있는 숫자면 `{ "type": "tooltip", "date": "2026-08-05" }` 두 칸이면 끝입니다.
설명을 받는 건 툴팁에 **없는** 값(가동률 같은)뿐입니다. 사람마다 답이 갈리는 자리라서요.

## 구조

| 위치 | 무엇 |
| --- | --- |
| `data/` | **기여 대상.** 직업 21개 · 전투 숙련 · 아티팩트 · 룬 조건부 옵션 (JSON) |
| `src/gen/` | `data/` 에서 생성된 파일. 직접 고치지 마세요 (`node tools/build-data.mjs`) |
| `src/runes-data.mjs` | 룬 90개의 이름·설명·수치. 생성기가 없어 직접 고칩니다 — 게임이 바뀌었을 때만 |
| `src/calculator.mjs` | 대미지 공식 A~L 항 |
| `src/build-evaluator.mjs` | 룬·아티팩트·패시브 → 공식 입력값 |
| `src/rune-app.mjs` | 추천기 화면 |
| `report.html` · `src/report-app.mjs` | 수치 제보 페이지 |
| `functions/` | 제보를 받는 서버 함수. **여기만 정적이 아닙니다** |
| `tools/validate-data.mjs` | 데이터 검증기 — 그럴듯하지만 틀린 기여를 막는 곳 |

설계 배경과 왜 이렇게 나눴는지는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 에 있습니다.

## 운영은 이 저장소 밖입니다

추천기 본체는 서버가 없어서 정적 파일 그대로 돕니다. 예외는 **수치 제보 페이지 하나**로,
Cloudflare Pages Function 과 D1 에 제보를 쌓습니다.

**운영 중인 사이트의 배포 설정·계정·도메인·비밀값은 여기에 없습니다.** `data/` 를 고치고
검증하는 데 필요하지 않기 때문입니다 — 위 세 명령과 `runes.html` 이면 충분합니다.

포크해서 직접 띄우시는 것은 [라이선스](#라이선스) 범위 안에서 자유롭습니다. 다만
그 경우의 배포 안내는 따로 제공하지 않습니다. `functions/api/reports.js` 는 `REPORTS_DB`
라는 D1 바인딩을 기대하고, 그 표 정의는 [`schema.sql`](schema.sql) 에 있습니다.
바인딩이 없으면 제보 API 만 503 이 되고 추천기는 그대로 동작합니다.
